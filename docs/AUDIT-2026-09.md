# Security & Logic Audit — 2026-09-01

Scope: full-repo audit of `main` after the v0.1.26 + develop unification (commit range `a78a682..aa8d8ef`). Performed with typecheck, lint, full test suite, manual code review, and targeted subagent audits of the HTTP surface and the agent-turn pipeline.

## Fixed in this pass

### Security

| # | Severity | Finding | Fix |
|---|----------|---------|-----|
| 1 | P1 | `pair/verify` rate limiter keyed on raw socket IP — behind the reverse proxy all clients share one bucket; 20 junk codes per 5 min deny pairing for everyone | Keyed on `cf-connecting-ip` / leftmost `x-forwarded-for` first (`clientIpForLimiting`) |
| 2 | P1 | Pairing code (the full credential) rode in a GET query string — lands in proxy/CDN access logs | `POST /api/pair/verify {code}` is canonical; GET-with-query kept as deprecated fallback for older desktops; desktop redeem now POSTs |
| 3 | P2 | `/oauth/finish/exchange` and `/api/pair/redeem` are pre-gate and each fire an outbound fetch with no local limit — cheap reflection DoS of the cloud | Fixed-window egress limiter, 10/min/IP, before any upstream fetch |
| 4 | P2 | `readBody` kept draining oversized bodies forever after 413 — unauthenticated socket-flood vector | Pause → let 413 flush → destroy (mirrors companion sidecar) |
| 5 | P2 | Any loopback Origin was trusted for CSRF on desktop installs (cross-port browser context could mutate bots/config) | Desktop-only same-origin mutation gate (`server/origin-gate.ts`): POST/PUT/PATCH/DELETE with an Origin must match the Host header, unless Bearer-token-authed. Cloud/self-hosted excluded (proxies rewrite Host; sessions gate) |

Reviewed and explicitly NOT changed:

- `always-allow` on the phone surface — removal was attempted and reverted: the shipped iOS app calls it (`Client.swift`), the harness 409s unless a card is pending, and `/respond` already grants one-shot approval power to a paired phone. Residual risk documented at the allowlist entry.
- Loopback-is-the-credential design — kept; the same-origin mutation gate closes the browser-context gap without a per-boot token.

### Logic flow

| # | Severity | Finding | Fix |
|---|----------|---------|-----|
| 6 | HIGH | A delegation whose queue was discarded while its approval card sat pending could still fire from the in-flight drain (`delegations.ts` snapshot iteration) | `processOne` re-checks queue membership immediately before dispatch; regression test added |
| 7 | MED-HIGH | Delegation acknowledged only AFTER the target turn — a crash mid-turn double-executes on restart despite the "crash-safe removal" comment | Acknowledged (removed + persisted) at dispatch time: at-most-once; a crash re-asks |
| 8 | MED | Watchdog's human-approval exemption had no ceiling — a permission request whose resolving event never arrives held a bot busy forever | 24h hard cap on approval waits (`TurnWatchdogOptions.hardCapMs`) |
| 9 | MED-LOW | Messages steered during a stall stayed queued after `settleLostTurn` (drain only ran on `turn.completed`) and fired on a later unrelated turn | Release timeout now drains queued sends |
| 10 | LOW | Provider-fallback one-shot consumed even when no alternate existed — owner adding a provider seconds later hit the full cooldown | `markAttempted` moved after the alternate check |
| 11 | LOW | Failed SQLite write in `appendMessage` aborted `turn.completed` housekeeping → bot stuck busy until watchdog | Memory stays authoritative; mdb failure logged and swallowed |
| 12 | LOW | `agent-core` stored the agent response under `task:<id>` but `getTask` cast it to `Task` | Stores the Task; typed generic memory API (`MemoryItem<T>`) replaces `any` dictionaries |
