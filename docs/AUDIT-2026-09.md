## Flaky test noted

`server/comms.test.ts` times out under full-suite parallel load (fake ACP fleet processes starve) but passes in isolation (~1s per test). Candidate for a retry decorator or a dedicated vitest shard.

**Resolved 2026-09-09.** Root causes were inverted time budgets, not CPU starvation alone: vitest config runs `fileParallelism: false` with CI-only `retry: 2`, but several comms tests carried per-test timeouts (40/45/60s) *below* their own internal poll deadlines (up to 90s), and the `beforeAll` boot hook timed out at 30s against a 90s server-start deadline — so under load vitest killed tests their own deadlines were about to let pass. All per-test timeouts now exceed their internal deadlines (120–200s), the boot hook gets 120s, and the file default stays 150s (`vi.setConfig`). Green in isolation (19/19).

### Live-site defect (found by browser testing muster.orazen.online)

- **Email sign-in was completely broken in production**: better-auth returned `403 INVALID_ORIGIN` for same-origin posts. Root cause: `docker-compose.prod.yml` sets `OMB_PUBLIC_HOST=${DOMAIN}`, Dokploy had no `DOMAIN` env → empty → `PUBLIC_BASE_URL` fell back to `http://127.0.0.1:8799` → the public origin was missing from `trustedOrigins`. Fixed with a safe default (`${DOMAIN:-muster.orazen.online}`) plus a loud boot warning when a self-hosted deploy lacks a public-host override.
- **All five desktop download links 404'd** (`/downloads/Muster.*` — no such static path exists). Repointed landing + download pages to the GitHub Releases `latest/download` assets (verified present for all five platforms).
- Verified good live: security headers (CSP, HSTS, nosniff, frame-ancestors), auth gates on `/api/bots` + `/api/config` (401), cross-origin POST refused, FAQ accordion functional, app shell renders.

### Concurrency (turn pipeline)

| # | Severity | Finding | Fix |
|---|----------|---------|-----|
| 17 | HIGH | Group member turn: busy-claim happened after `await connectedAppsIntegration(...)` — the same bot in two rooms could pass the busy check in both chains and dispatch two concurrent provider processes | Claim `setActivity(..., "working")` synchronously before the await; early return releases it |
| 18 | MED | Stale `turn.completed` from an interrupted-but-alive provider can settle a newer turn after watchdog release (matched by threadId only) | **Closed 2026-09-09**: provider terminal events settle via `settleIfCurrent(threadId, turnId)` — matching turnIds prove the current generation, differing ids are dropped, and a 60s guard window (`suppressStaleSettles`, armed by `settleLostTurn`) covers id-less completions. Harness-owned completion paths keep plain `settle()` |
| 19 | LOW-MED | SSE broadcast ignores `write()===false` backpressure; a cellular client buffering hundreds-of-KB screen frames can grow memory unbounded | **Closed 2026-09-09**: all SSE writes route through `sseWrite()` with per-client byte accounting; past `SSE_CLIENT_CAP` (4 MB) the client is dropped and destroyed, `drain` resets the counter |
| 20 | LOW | Liveness reaper attributes a journalled child death to the oldest matching watched turn across threads — can mis-attribute across turns | **Closed 2026-09-09**: all four engine drivers emit `turn.engine-pid` at spawn; watchdog binds it (`noteEnginePid`) and the reaper attributes an exact `death.pid === turn.pid` match first, falling back to the spawn-time window only for pid-less turns (pid-bound turns are never blamed for another process's exit) |
