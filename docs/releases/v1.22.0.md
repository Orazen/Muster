# Muster 1.22.0

Clearer setup, more expressive teammates, and a repaired automatic Local VM flow.

## Added

- **One account setup flow.** Connect Google Drive, optionally connect Gmail, and configure an AI provider from the same onboarding experience. Desktop users see installed engine status and setup steps; web users can bring an API key. Each connection shows its own permission and status.
- **Teammate appearance previews.** Choose a mascot character and colour with a larger preview. Try Ready, Working and Resting animations without changing what the bot is actually doing.
- **Clearer group conversations.** Named participant cards make it easier to see who belongs to a room and which teammate is working there. The participant strip scrolls on narrow screens.
- **Message delivery status.** Messages show when Muster is checking delivery, waiting to send, or has sent the request. An uncertain outcome stays visible for review instead of being silently resent after a disconnect.
- **See where your bot browsed.** The Browser panel shows the agent's latest observed page, with an action to open it in the separate preview.
- **Disconnect Drive from Muster.** Remove this installation's stored Drive connection from backup settings. Existing Drive backups remain available; revoking Google's authorization is a separate action in your Google account.

## Improved

- **Automatic Local VM setup.** Fixed Podman being reported as stopped when it was running. Setup can install the runtime when missing, start it, prepare Cua and create or resume the desktop with progress and actionable errors. macOS and Windows use their own runtime commands and installation paths.
- **Existing VM preservation.** Setup reuses an eligible Podman machine and recognises the prepared container correctly. Existing machines are not reset or automatically resized. A new macOS Podman machine uses 6 GB of memory and two CPUs; the desktop container remains capped separately.
- **Sign-in and pairing.** A failed API request no longer automatically throws a valid session back to sign-in. Desktop sign-in is tied to the attempt that started it, with cancellation and expiry handling. Pairing guidance now distinguishes nearby/Tailscale access from a publicly reachable HTTPS address.
- **Backup recovery.** Restore uses the connected account's Drive when appropriate, loads restored data in the right startup order, preserves recovery copies, and reports refused or failed restores with useful next steps. Repeated attempts no longer get stuck because a previous backup directory exists.
- **Task reliability.** Parallel-thread limits now admit the configured concurrency. Recovered errors stop holding a bot at the top of the attention inbox, and a turn ending without a reply reports that outcome.
- **Account data handling.** Corrected account ownership for team briefs, routines, memory, delivery receipts and restored records. Invalid memory entries no longer discard unrelated valid facts. Hosted usage-allowance records survive restarts.
- **Keyboard and touch controls.** Improved sign-in tap targets, kept keyboard focus inside the command palette, and adjusted setup and appearance controls for smaller screens.
- **Website and account entry.** Added an interactive ecosystem showcase, mascot reactions, refreshed sign-in presentation, and download information read from the published release manifest.

## Platform notes

- These downloads update the desktop app. They do not publish new iOS, Android or Apple Watch builds, and the hosted web app requires its own deployment.
- Connecting Drive does not enable automatic backup or continuous sync. Encrypted backup and restore remain desktop features.
- The repaired Local VM flow was exercised on macOS with Podman and Cua, including a restart and workspace persistence. Windows setup has automated coverage; a fresh Windows machine/WSL acceptance pass is still outstanding.
- Windows installers are unsigned and may show an unknown-publisher prompt.
- A real Google sign-in on the newly installed desktop build remains an acceptance check. Cloud-assisted sign-in also requires the matching hosted server changes.
