# Muster 1.22.1

Fixes for Local VM selection, Mac permissions and browsing with API-key providers.

## Fixed

- **Local VM stays independent of Mac permissions.** VM, Cloud, Sandbox and Off no longer display the This Mac activation prompt. Selecting This Mac opens its explicit permission setup without silently enabling control.
- **Correct Mac permission owner.** The packaged embedded driver checks Muster’s own permissions. A separate CuaDriver installation can no longer incorrectly block it. Permission errors name the right app and offer separate Screen Recording and Accessibility settings buttons; macOS still requires the user to grant access.
- **The right VM for each bot.** Computer preview status and screenshots use that bot’s assigned desktop under per-bot isolation. Missing per-bot desktops explain that they start with the next task. Readiness refreshes while the panel is open, and Off stops its preview polling.
- **Direct VM setup.** “Open Local VM setup” now opens the Local VM settings tab instead of General.
- **Predictable Auto mode.** Opening an ordinary bot’s Computer panel no longer creates a new cloud box merely because a cloud provider is configured. Explicit Cloud selection and the cloud-native Computer engine retain their existing provisioning behavior.
- **Browsing with compatible API providers.** OpenRouter and other OpenAI-compatible engines now advertise the custom MCP support already provided by their tool loop, so an enabled bot browser can be attached to a turn.
- **Fresh browser preview setup.** Corrected Chrome for Testing download URLs and the extracted Mac executable path. The installer preserves operating-system quarantine settings.

## Maintenance

Includes the OpenSandbox 1.1.0 and Vite 8.3.1 dependency upgrades that merged after 1.22.0 was pinned.

## Scope

The bot’s browser tools and the separate preview still have distinct sessions; preview sign-ins are not transferred to the bot. A unified interactive browser workspace and a native Swift Mac app remain future work. This patch does not publish new mobile or Watch builds. Windows remains unsigned, and real Windows VM acceptance is still outstanding.
