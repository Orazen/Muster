# Foreground Watch call protocol — implementation contract

Loop137 foundation for the accepted Watch calling journey. Existing pairing and
bot ownership remain authoritative. This does not enable background incoming
calls, microphone streaming, device selection, or durable offline execution.

## Wire contract

All routes are under `/api/bots/:botId/calls`. They require the existing host
account/bot authorization (or installation loopback trust), and the companion
must separately authenticate a full-access paired device. Each call carries
`X-Muster-Call-Token`, a fresh 32-byte lowercase hex capability generated by the
client. Retain it only for the foreground call; never log or return it. The
server stores its hash. Another paired device cannot read or end a call without
that capability. The proxy forwards this header only on the explicit call family.

- POST collection: `{requestId, threadId}`; UUID requestId becomes call id.
  Returns 201 `{call}`; same identity/body/capability returns the same call.
- GET `/:callId`: returns `{call}` and renews an active foreground lease.
- POST `/:callId/accept`: `{}`; ringing → connected, duplicate accept is harmless.
- POST `/:callId/messages`: `{requestId, text}`; 1–8000 trimmed characters,
  UUID requestId. Connected only; one turn at a time. Duplicate identity and
  same text returns the original receipt; changed text is409. Never resend an
  uncertain dispatch automatically. Bot must still be on the captured thread
  and idle; this path does not enqueue work behind unrelated work.
- POST `/:callId/end`: `{}`; invalidate before awaiting exact-turn cancellation.
  Repeated end is harmless. Never interrupt a newer turn or another task.

`call`: `{id, botId, threadId, state, revision, expiresAt, endReason?, turn?}`.
States: `ringing | connected | ended`; revision integer, expiresAt Unix ms.
`turn`: `{requestId, state, messageId?, reply?, error?}` where state is
`starting | working | completed | failed | uncertain | cancelled`.
Call endReason is a readable string when ended. Reply bounded to16000 characters.
No raw tokens, provider errors or private transport details in wire errors.

The in-memory registry retains idempotency receipts/tombstones for a bounded
period (maximum200 calls). Active lease45 seconds, refreshed by explicit reads;
an owned expiry sweep ends stale calls and attempts exact-turn cancellation.
Restart loses foreground sessions and returns404; clients must explain unknown
work state, never recreate/resend it silently. Durable queue/recovery is later.

## Execution and cancellation

Ring/accept do not start model work. Explicit message submission creates one
receipt before asynchronous dispatch. Normal startTurn remains the only engine
entry. Capture its peer lease and original message identity, check call validity
through setup, and correlate runtime events by provider and turn identity.
Terminal/later events must not resurrect an ended call. Ending or lease expiry
may stop only that captured lease; a superseding turn stays untouched. Transport
failure while ending is shown as uncertainty, never a claim the host stopped.

## Slice boundary and proof

This first foundation slice implements host lifecycle/routes, deliberate companion
allowlisting/header forwarding, and Swift wire/client/coordinator contracts.
The next slice connects Watch views/session and an explicit daily-planning call.
Foundation tests cover scoped tokens/accounts, duplicate requests, no work before
accept, lost acknowledgments, end/expiry versus asynchronous dispatch, changed
thread, superseding work, late events and proxy restrictions. Swift tests use
owned transport fixtures. Actual wrist audio, interruptions/backgrounding and
all-platform acceptance remain open. No completed calling claim from this slice.
